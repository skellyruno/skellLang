# SkellCipher Crypto: threat model

**Status: experimental source encryption and offline recovery, not independently audited.**

Protected assets: private SkellLang source and DSP/UI algorithms, Windows vault master keys, offline encrypted key backups, recovery passphrases, compiler plaintext and derived artifacts. Attackers include unauthorized source-repository readers, unauthorized AI agents without keys, malicious changes to ciphertext, leaked CI artifacts, stolen portable backups and compromised development PCs.

Current controls: established AES-256-GCM authenticated encryption of source using per-file HKDF-derived keys; canonical authenticated, versioned and bounded metadata; fresh CSPRNG salts and nonces; strict rejection of wrong keys/version, tampering or unauthorized resolver with no plaintext fallback; encrypted-only compile in memory with source-neutral errors. Windows storage requires Windows Credential Manager and rejects unapproved keyrings. Root key rotation preserves old ciphertext. Offline recovery uses scrypt and AES-256-GCM with authenticated versioned backup metadata, explicit password prompts (not command-line args), exclusive file creation and no overwrite of existing stored key ID. Tests include ciphertext tampering, unauthorized access, recovery corruption and real Windows ephemeral restore.

Residual risks: source length and key ID metadata are visible. Encryption cannot prevent rollback to older *valid* ciphertext, deletion, or denial of service. Weak human-chosen recovery passwords can be brute-forced if backup stolen; use random high-entropy secrets and independent offline custody. Python immutable bytes cannot be securely erased; malware running as the authorized Windows user can inspect memory or Credential Manager. Original plaintext, editor backups, swap, crash dumps, compiler-generated Studio JSON/C++, and compiled VST3 binaries can expose code/IP. An authorized developer or AI with plaintext can read it. CI filename scanning is not comprehensive secret scanning; third-party dependencies and build runners can be compromised.

Outstanding gates: independent crypto audit, password recovery test on an actual user PC, dependency provenance and vulnerability checks, stronger Windows file ACL enforcement and local anti-rollback policy, SkellForge encrypted unlock integration, compiler output/crash/log/CI artifact leakage scans, version migration fixtures, native SkellLang-to-SkellNative VST3 and FL Studio parity. Do not claim unbreakable security or reverse-engineering protection.
